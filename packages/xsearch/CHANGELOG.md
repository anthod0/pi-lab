# Changelog

All notable changes to `@pi-lab/xsearch` will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added

- **twitterapi.io backend.** `xsearch` works with `TWITTERAPI_IO_API_KEY` as an alternative to `XAI_API_KEY`, for anyone who would rather use an API key from there. The backend is chosen from your credentials, and `backend` pins one when both keys are set. Retrieval is metered at 15 credits per returned post — $0.15 per 1,000 — against $5 per 1,000 posts fetched for `x_search`, so the same volume costs roughly 33x less. twitterapi.io returns raw posts rather than an answer, so the retrieved posts are passed to the configured `xsearch.synthesisModel` under a citation-constrained prompt, and the tool keeps the same answer-plus-citations shape as the xAI backend.
- **Search modes.** `mode: "users"` finds accounts through `/twitter/user/search` and answers with profile URLs as sources; `mode: "thread"` reads a post's thread context through `/twitter/tweet/thread_context`, accepting a post id or a permalink. With keyword search this covers everything `x_search` does except semantic search, which twitterapi.io has no equivalent for. Both modes share the retry, pacing, cancellation and citation handling, and both disclose truncation. Thread mode passes your question to synthesis and identifies the thread in `## Notes`; on the xAI backend a thread request appends the thread reference to the query, which is where its native search reads it from. A mode refuses parameters it cannot use: handle filters, dates and `queryType` for accounts, and those plus `count` for threads. `mode`, `tweet` and the question itself are validated before credentials are read.
- **Date windows that account for the upstream boundary.** twitterapi.io resolves `since:`/`until:` at 04:00 UTC, so for offsets east of UTC−4 the newest `4 + offset` hours of each scan fall outside the requested local day and, since results arrive newest-first, sit in front of the matching posts. Pages discarded by the trim are not charged against `maxPages`, so a busy topic cannot spend the whole budget crossing the band before reaching the window; the discarded count and the band size are disclosed in `## Notes`. Filters are read as the caller's local calendar days, and boundaries are resolved per date, so DST transitions are handled for midnight-switching and 02:00/03:00-switching zones alike.
- **Pagination that follows the upstream cursor.** A page that is empty, or that only repeats posts already held, does not end the walk while more pages remain. Stopping early is reported as truncation, and a truncated retrieval with no results says so instead of claiming nothing matched. A missing cursor counts as truncation, except once `count` is satisfied or when an empty page ends a thread walk, both of which are complete results.
- **Media understanding.** With `enableImageUnderstanding`, post images are attached to the synthesis request for models that accept image input, with a manifest tying each attachment to its post permalink. With `enableVideoUnderstanding`, video posts contribute their poster frame instead of the video itself, and the result says so. Downloads follow the caller's cancellation, carry a deadline that covers the body read, reject non-image and declared-oversized responses before reading, enforce the byte cap while streaming, and are bounded to three attempts per allowed attachment and 60 seconds per search, with anything skipped disclosed.
- **Retries and error reporting.** Only 429 and 503 are retried, the provider's documented safe scope; other statuses surface immediately instead of repeating a request that may already have been billed. `Retry-After` is honoured in numeric and HTTP-date form and never shortened: a zero delay falls back to `retryBaseDelayMs`, and a delay beyond the 60-second cap fails with a message naming the requested wait. An HTTP 200 whose body cannot be read is not retried, and says so. HTTP failures always report their status, including non-JSON bodies. A depleted balance returns `{error, message}` rather than `{detail}`/`{msg}`, so HTTP 402 reports `payment required: Credits is not enough.Please recharge` and is never retried.
- **Citations matched to what was retrieved.** Only x.com / twitter.com URLs can match by status id, so a look-alike URL on another domain is never treated as a source. A link that matches nothing is dropped from `## Sources` and reported in `## Notes`; with no inline citations at all, `Sources` lists the posts the search retrieved, matching the xAI backend. Duplicate detection registers both the id and the permalink of each occurrence, so alias chains collapse to one post.
- **Model handling.** `xsearch.model` is used only by the xAI backend; the twitterapi.io backend requires `synthesisModel` and fails with an actionable message when it is missing, rather than reusing an xAI model id from a different namespace. Resolution accepts the `provider/<model>` short form for providers that namespace their own model ids, reports ambiguity with its candidates, and lists what a provider does expose when an id cannot be found. The backend is also feature-detected against the pi version: a registry without `complete` fails fast with a message naming the requirement instead of `TypeError: registry.complete is not a function`.
- **New settings:** `synthesisModel`, the pi model that writes the answer on the twitterapi.io backend; `backend` (`auto`, `xai`, `twitterapi`); `maxMediaPerSearch`; `minRequestIntervalMs` (default 5 s, so pagination respects the per-key QPS ceiling); `retryBaseDelayMs`, which is also the floor for `Retry-After`; `maxPages`; and `maxPagesCeiling`. Page settings are capped at 100, with `maxPages` never above the ceiling; anything outside the accepted range falls back to the default.
- **New tool parameters** for the twitterapi.io backend: `count` (default 10 for posts, 20 for accounts; max 50) and `queryType` (`Latest` or `Top`).
- `XSearchDetails` gained an optional `notes` field, rendered as a trailing `## Notes` section, so the tool can disclose coverage gaps, skipped media and dropped links without changing the contract. xAI's document parsing also surfaces `x_posts_fetched` and `x_users_fetched`, which xAI bills separately from calls.
- A failed synthesis is an error rather than an empty answer: `stopReason` values of `error`, `aborted` and `toolUse`, and unexpectedly empty successful completions, are rejected instead of being reported as a successful result with real sources attached.
- `searchX` accepts an optional `AbortSignal`, so a cancelled tool call stops the request.

### Changed

- Handle filters accept up to 20 handles, raised from 10.
- `XSearchConfig` gained `backend`, `maxMediaPerSearch`, `minRequestIntervalMs`, `retryBaseDelayMs`, `maxPages`, `maxPagesCeiling` and the optional `synthesisModel`. Consumers constructing config literals must add all of them except the optional `synthesisModel`.
